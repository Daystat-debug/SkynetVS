# Вопросы по коду в режиме `--auto`

В экспериментальном CLI можно спросить о прямых вызовах функции или о происхождении поля отчёта. В диалоге достаточно ввести вопрос и при необходимости ответить на уточнение. Для разового запроса передайте текст аргументом:

```powershell
.\.venv\Scripts\python.exe -I -S -B tools/skynet_explain.py --auto
.\.venv\Scripts\python.exe -I -S -B tools/skynet_explain.py --auto "Где вызывают функцию с параметрами window и stride? Какие значения им достаются?"
```

Во втором примере CLI определил по сигнатуре функцию `modules_from_source`. Вызывающая функция `module_rank` передаёт `path` и `src`. Аргументы `window` и `stride` получают значения по умолчанию 24 и 18. В консоли есть ссылки и на основание выбора, и на доказательство вызова. [Сигнатура](https://github.com/Daystat-debug/SkynetVS/blob/c6acb52/modules/developer_task_ui/app/retrieval/m130_rank.py#L26) · [Вызов](https://github.com/Daystat-debug/SkynetVS/blob/c6acb52/modules/developer_task_ui/app/retrieval/m130_rank.py#L69)

Другой пример — «Откуда в строке отчёта количество модульных участков, если результатов мало?». Здесь выбран анализ поля `candidate_modules`. В пустом случае третий элемент результата `module_rank` равен нулю, при обычном возврате — длине `windows`. Далее значение переносится через `module_candidates_total` в публичное поле. Чтение поля при форматировании подтверждается отдельно. Вызов форматирования с конкретным экземпляром отчёта по этим источникам не устанавливается. [Возвраты](https://github.com/Daystat-debug/SkynetVS/blob/c6acb52/modules/developer_task_ui/app/retrieval/m130_rank.py#L69-L93) · [Поле отчёта](https://github.com/Daystat-debug/SkynetVS/blob/c6acb52/modules/developer_task_ui/app/context_search.py#L167) · [Форматирование](https://github.com/Daystat-debug/SkynetVS/blob/c6acb52/modules/developer_task_ui/app/context_search.py#L211)

## Выбор и уточнения

Маршрутизатор использует формулировку для определения операции, а для выбора цели — имена и параметры функций, процитированный текст из тела функции, ключи возвращаемых словарей и русские подписи в исходниках. При единственной цели он вызывает существующий статический инструмент. Автором объяснения и проверяемых ссылок остаётся этот инструмент. Результат сравнивался с прямым вызовом по всем полям исходного ответа, включая ссылки. Генерация для этого не потребовалась. [Код выбора](../../../tools/skynet_auto.py)

При неоднозначном счётчике пользователь видит подходящие подписи. В интерактивном режиме можно ответить номером или подписью, например «Модульных участков». Если не названа функция, можно следующим сообщением ввести имя. Новый самостоятельный вопрос заменяет уточнение; контекст не сохраняется между процессами. Общая проверка доступа выполняется и для уточнений. Область чтения — те же три файла в Git. Свободная генерация не включается.

Итого **15/15** верных решений, **7/7** правильных целей при вызове инструмента и **7/7** совпадений содержательного результата с ручным выбором, включая ссылки. Из семи результатов пять полных, один ограниченный и один обоснованный отрицательный. Ложных маршрутов и лишних отказов на этом наборе — **0**. Все **38/38** выведенных в разовых вопросах ссылок (23 различных диапазона) сверены по commit, пути, диапазону, Git blob и SHA-256. Обе зафиксированные последовательности с уточнением дали ожидаемый результат, их ссылки также проверены. Максимальное время разового вопроса после открытия снимка — 0,134 с; замеры включают инструментацию, каждый выполнен один раз.

**Известные ошибки.** Отдельный прогон прежних D0/F1–F7 и S1–S4 дал **10/12** верных автоматических решений. В S1 оборот «куда записывает результат» был принят за второй запрос о происхождении поля, хотя назначение результата уже объясняет инструмент прямых вызовов. В F7 оборот «какая функция передаёт» не был распознан как запрос о вызывающем коде. В обоих случаях CLI попросил лишнее уточнение. Вызовов другого инструмента не было. При прямом выборе режима все восемь прежних результатов `--flow` и четыре результата `--calls` совпали с исходными структурированными ответами и ссылками. [Регрессионный прогон](regression.json)

Первый вариант `ecfd388` дал четыре ошибки на 17 синтетических вопросах: спутал размер объекта со счётчиком, упустил отрицание и вопрос о памяти, не распознал «из какого кода». Во второй итерации добавлены проверка полной подписи, ограничения для отрицаний и неподдерживаемых операций, раздельный выбор целей при смешанном запросе. Все 17 синтетических случаев и проверки продолжения диалога проходят. Результаты на двух небольших наборах не устанавливают точность для всех русских перефразировок. Режим работает с поддерживаемыми статическими операциями и наблюдаемыми признаками цели. В частности, явное ограничение поиска одним файлом требует уточнения. **Две итерации, 0/12 генераций Qwen.**
