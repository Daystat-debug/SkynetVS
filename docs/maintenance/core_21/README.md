## Какие пробелы удалось разрешить

- Точная последовательность причин пробела совпала с авторской рубрикой в 19/20 задачах. Уточнение задано в 12. Во всех 12 выбраны ожидаемые часть и предмет вопроса. Для 10 из них имелся скрытый положительный объект для проверки меню. Он был в пуле в 10/10, в коротком показе в 8/10. Пропущены R2 и R4. Объект оставался доступен свободной реплике. Кандидат в меню сам по себе не даёт права публиковать факт.
- За те же 12 вопросов полный список предъявил 83 варианта (3 708 символов по метрике протокола), короткий — 26 (2 039 символов). Суммы включают вопрос о виде требования. Явный выбор дал новый факт в 9 и 8 случаях соответственно. Свободный ответ — в 7/12 при обоих показах. Симулятор даёт одинаковую свободную реплику при совпадении части и оси, поэтому эти данные не измеряют, какое оформление помогло бы человеку лучше сформулировать ответ.
- Не зарегистрировано привязок к чужому размеченному объекту. В R3/B6 распознано отсутствие буквальной метки в каталоге. В A8 обе трактовки оставались возможными после ответа «Не знаю». В A6 известен объект и найдена его строка, но доказательства прямого вызывающего нет. В R5 сохранена строка с ошибкой, для фактической частоты появления нужны наблюдения исполнения.
- В A5 и B5 система сохранила оба ранее доставленных бесспорных факта (по одному на задачу) и после уточнения нашла вторые. В A5 реплика «Из зала в запасник» позволила связать нужный объект с прямым статическим вызовом из `inspect_archive_motion`. Смена направления относится к другому объекту. Все прежние правильные факты сохранились во всех четырёх вариантах продолжения.

## Что не получилось

- **R2, настоящий код.** Цитате `M127_OLD_SOURCE` соответствуют несколько меток. В коротком показе не оказалось варианта ошибки пути. Слово `PATH` в свободной реплике выделило его в сохранённом пуле. После нового вызова хост доказал место в `extract_symbols`, строка 37. [Исходник на контрольном снимке](https://github.com/Daystat-debug/SkynetVS/blob/f0a23772fd15c50c00a87383cf9e6f641cc120a7/modules/developer_task_ui/app/retrieval/m127_symbol.py#L36-L37)
- **R4.** Указание `TITLE INVALID` совместимо с `M127_TITLE_INVALID` и `M130_TITLE_INVALID`. Обе гипотезы были получены. Короткий показ вывел два посторонних описания. Даже в полном списке ответ симулятора не различает эти две ошибки. Бюджет в одно уточнение исчерпан.
- **A4 и B2.** Выбор номера разрешил объект. Свободные объяснения про «специалиста по восстановлению» и «зрительный зал» не установили соответствие с реставратором и публикой. В данных нет подтверждения приобретения этих смысловых знаний.
- **A3.** Пользователь успешно выделил разрешение выдачи рукописи. При повторном планировании вопрос о месте записи был принят за запрос внешних сведений. Подтверждённый объект сохранился, требуемый факт не доставлен.
- **A7.** Для «Расскажи про …» система уверенно указала место. В карточке пользователя требовалось условие. Проверка не обнаружила неопределённый вид требования, предложение уточнить не появилось. Это единственная ложная полнота во **всех** вариантах. Подлинность ссылки здесь проверена. Текст пользователя действительно допускает несколько прочтений, поэтому целевой сбой — безоговорочная публикация одного из них.
- **B7.** Конфликт интерпретаций вызвал вопрос о виде доказательства. Ответ «Только место в коде» восстановил факт. Сильный 0.16 дал правильное место с первого раза. Хотя по рубрике все заданные вопросы попали в намеченный пробел, один ход здесь фактически был лишним относительно базового решения.

## Архитектурный вывод

Для явного выбора обоснован простой список с полным пулом. Короткое противопоставление снижает объём чтения и иногда скрывает нужный вариант. Проверка ссылки и повторный сбор на том же Git-снимке позволяют безопасно продолжить задачу, но не устраняют отдельную ошибку в определении требуемого вида ответа. На этой серии содержание свободной реплики распознавалось через лексические различия. Семантически близкие высказывания без общих слов, надёжность при сложном отрицании и полезность конкретной формулировки вопроса для людей остаются открытыми. Автоматического долговременного обучения и обновления штатных компонентов нет.

## Воспроизведение

Из корня репозитория в PowerShell. Для живого примера используется текущий Git HEAD в разрешённых пяти файлах. В автоматическом повторе создаются те же два временных Git-коммита. Ссылки синтетических программ воспроизводимы в этих клонах; соответствующие синтетические коммиты не публикуются как исходники проекта.

```powershell
$py = '.\.venv\Scripts\python.exe'
& $py -I -S -B tools/skynet_dialogue.py 'Где возникает ошибка «M127_OLD_SOURCE»?' --interactive
# В свободном ответе можно ввести: Меня интересует PATH, имя файла.
& $py -I -S -B tools/test_active_dialogue.py
& $py -I -S -B tools/eval_active_dialogue.py verify
```

Первый вызов CLI выводит проверенные утверждения и меню. Уточнение потребляется однократно. Тесты контролируют неизменность HEAD, подмену старой ссылки, путь вне области и повторное продолжение. Все 64 команды завершились с кодом 0, включая 61 проверку из реестра 0.20, дополнительный аудит 0.20, тесты диалога и его воспроизведение. Повтор совпал по всем индивидуальным оценкам и распакованному журналу, исключая изменчивое время. [Результаты проверок](checks.json)
