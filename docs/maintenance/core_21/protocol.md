# Core 0.21 · разрешение одного смыслового пробела

Исходный Git HEAD для лабораторных программ — `f0a23772fd15c50c00a87383cf9e6f641cc120a7`. Гипотеза: в части задач источник уже различает объекты, но доступ к нему не сообщает, какой из конкурентов интересует пользователя. Один ответ о различающем свойстве может дать исследователю 0.16 недостающую привязку. Альтернативная гипотеза: номера в полном списке дают столько же полезной информации и требуют меньше инженерных механизмов.

## Механизм и контроль

Контур `skynet_dialogue.py` открывает HEAD штатным лабораторным хостом. Объект с дословной последовательностью слов или с явно указанным уникальным владельцем может быть найден до диалога. Поиск и подтверждение остаются раздельными. Меню получает описания из уже проверенного статического каталога. Явная подстрока с несколькими совпадениями означает несколько допустимых референтов. При пересказе без подтверждения фиксируется нехватка знания интерпретатора. Отсутствие цитаты устанавливается только в построенном каталоге. Иные причины включают конфликт двух прочтений операции, отсутствие статического доказательства и недоступные сведения о запуске. Вопрос задаётся по первому разрешимому пробелу. Проверяются исходные доказательства, а уточнённый вопрос проходит обычную проверку хоста на том же коммите. Свободный ответ интерпретируется по уникальному непрерывному отличительному фрагменту. Это проверяемая лексическая гипотеза, способная ошибаться при смысловом пересказе.

Первый вызов и максимум один новый Task. Каждому доступны прежние 6 шагов, 96 элементов и 25 с. До 12 шагов, 192 элементов и двух окон по 25 с за диалог, без учёта времени пользователя. Меню ≤16 кандидатов на пункт, на экран выводятся два контраста либо весь список. Обе стратегии используют один каталог, порядок, общий бюджет и правила интерпретации. Отрицательный или нераспознанный ответ исчерпывает попытку. Повторных генераций, обучения и исполнения анализируемого кода нет.

## До заключительной серии

Фиксируются алгоритм, автоматический независимый от решений планировщика оценщик, правила симуляции и контроль границ. Затем отдельным коммитом фиксируются новые программы, вопросы, авторские ответы и рубрики. После первого предъявления изменения алгоритма и оценщика исключаются. Исходные модели 0.19 и 0.20 используются с сохранёнными параметрами. Четыре автоматических ориентира: 0.16, 0.19, 0.20 и расширенное лексическое ранжирование. Сравнение с участием пользователя — полный список и вопрос о различии. Сначала отдельно оценивается полностью самостоятельный первый ход.

Симулятор получает только видимый вопрос, канал ответа и карточку намерения пользователя. В карточке заранее закреплены номер части и ось уточнения, текст свободного ответа и различительный текст для выбора видимой опции. При несовпадении оси или части ответ «не знаю». В канале выбора возвращается номер только при единственном видимом совпадении, иначе «ни один». В свободном канале материал реплики одинаков для обоих интерфейсов. Симулятор не читает Git, гипотезы, разметку доказательств или результаты. Авторская разметка и симуляция без независимой человеческой проверки.

Оценка каждого факта требует правильных координат Git, вида запроса, подлинной ссылки на исходное выражение и непосредственного доказательства требуемого вида. Правильный полный ответ требует всех фактов и статуса answered. Полезный частичный содержит хотя бы один факт. Ложная полнота — answered при нарушении полной рубрики. Для отрицательных требований проверяется отсутствие чужого прямого ответа. Раздельно сохраняются причины пробелов, попадание правильного кандидата в пул/показ, ошибочные привязки и виды, сохранение уже доказанных фактов, уместность вопроса, доступные для выбора варианты, видимые символы, факты после одного ответа, число шагов и задержки. Точное соответствие причины пробела и уместность вопроса оцениваются по авторской рубрике до уточнения. Польза вопроса дополнительно требует фактически доставленного нового факта. Ненужным считаем вопрос в случае, где рубрика вообще не требует участия пользователя. Показ и автоматическая интерпретация считаются раздельно. Выводы о человеко-минутах и качестве свободного разговора из симуляции не следуют.
