# Откуда приходит поле отчёта

Экспериментальный режим `--flow` читает AST трёх разрешённых файлов в Git. Он объясняет происхождение одного поля возвращаемого словаря по его имени или русской подписи в выводе. Каждый шаг содержит ссылку на строки выбранного коммита. В запуске не участвуют Qwen, голосовой runtime или выполнение прослеживаемого Python-кода.

```powershell
.\.venv\Scripts\python.exe -I -S -B tools/skynet_explain.py --flow "Откуда берётся число функций-кандидатов и как оно попадает в итоговый отчёт?"
```

В этом примере `rank` вызывает `rank_symbols(title, selected, limit=100)`, берёт `sym['symbol_candidates']` и возвращает это значение в поле `function_candidates_total`. Реализация `rank_symbols` находится за границей доступных исходников. [Вызов и возвращаемое поле](https://github.com/Daystat-debug/SkynetVS/blob/ebb901a/modules/developer_task_ui/app/retrieval/m130_rank.py#L125-L135)

В другом файле `search_repository` сохраняет результат `rank(effective, sources)` в `base` и переносит значение в публичное поле `candidate_functions`. Функция `format_context` читает именно этот ключ под подписью «функций». По разрешённым файлам нельзя установить, кто передал ей конкретный экземпляр отчёта. В CLI эта граница указана рядом с местом чтения. [Формирование отчёта](https://github.com/Daystat-debug/SkynetVS/blob/ebb901a/modules/developer_task_ui/app/context_search.py#L153-L167) · [Чтение при форматировании](https://github.com/Daystat-debug/SkynetVS/blob/ebb901a/modules/developer_task_ui/app/context_search.py#L207-L211)

## Надёжность и границы

На исходном `ebb901a` в 11 контролируемых случаях `--calls` выдавал четыре ложные связи. Это были замена экспортированного имени после объявления, декоратор с неизвестным результатом, захват имени в `match` и возможная замена глобального имени из другой функции. После изменения все 11 ожидаемых решений воспроизводятся. Обычный относительный импорт с псевдонимом по-прежнему разрешается. Четыре ранее принятых результата S1–S4 совпали с сохранёнными структурированными ответами, включая ссылки. [Исходный отрицательный результат](calls_before.txt) · [Проверки разрешения имён и потока](../../../tools/test_flow_reader.py)

Трассировка поддерживает словари со статическими ключами, прямые вызовы функций верхнего уровня, однозначные присваивания, распаковку возвращаемых кортежей и простые ранние возвраты. При возможной записи в словарь, передаче контейнера неизвестному коду, неподдерживаемом возврате или недоступной реализации выводится последняя подтверждённая операция. Подписи для русских вопросов извлекаются из f-строк исходника. Для поля без такой подписи можно ввести его точное имя. Анализ ограничен видимыми лексическими связями доверенного Git-снимка; динамическая подмена при выполнении, произвольный Python и фактические значения в памяти остаются за его пределами.
