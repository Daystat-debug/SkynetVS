# M289. Естественные русские вопросы к исходному коду

## Граница эксперимента

Отправная точка — чистая экспериментальная ветка на `d5b5f26dc06ec1e617f2c3a5dcae07c8bc26b5eb`. Десять вопросов Q, типы оснований, проверяемые функции и группы опорных строк зафиксированы до написания алгоритма отдельным коммитом `09d8dc930effe79c1304629f155156224db45537`. В Q семь отвечаемых вопросов, в том числе три о связи между файлами. Остальные три требуют уточнения, отсутствующей статистики или живого наблюдения. В формулировках нет имён Python. Это небольшой открытый авторский набор. H, N и P использованы для регрессии. [Контрольный набор](control.json)

## Два изменения и способ проверки

**A** — исходные scoped-поиск и многофрагментная сборка. **B** — добавлен только экспериментальный поиск по кириллице. Он разбирает те же три разрешённых Git-источника штатным извлечением функций. Для русских слов длиной от четырёх букв берётся префикс длиной четыре, ё нормализуется в е, небольшой список служебных слов пропускается. Для продвижения функции нужны два разных префикса вопроса в одной строке определения или его тела. Порядок определяется числом совпавших префиксов на лучшей строке, при равенстве учитывается исходный ранг. Оставшиеся позиции заполняет M130. Алгоритм не использует эталонные пути, номера строк, имена функций или пары «вопрос — ответ». [Реализация поиска](../../../tools/m289_russian.py)

**C** использует выдачу B. Добавлен только запасной способ допуска при прежней причине `NO_CODE_MENTION`. В первых четырёх кандидатах он ищет такую же локальную опору в пределах доступного структурного просмотра. При конкуренции разных мест с тем же лучшим набором префиксов сборщик отказывает. Дополнительное окно должно покрыть не менее двух других префиксов. Опорная строка целиком входит в каждое окно. Прежние отказы для отсутствующего явного идентификатора, живого состояния и выхода за область продолжают действовать. Сохраняются штатные инспекции, проверка commit/blob/диапазона, пределы в три ссылки, 3000 байт исходника и 3584 байта системной строки вместе с JSON. [Правило допуска](../../../tools/m289_russian_context.py)

Измерение проходит через настоящий `ground289.answer` до отказа или вызова provider. В обоих последовательных сравнениях порядок вариантов меняется между двумя повторами каждого вопроса. Используются свежие сессии на прогретом Git-снимке `e67c9ad013f4fa451046b9c461e8f055db8beaaf`. Поиск видит только вопрос и разрешённые исходники. Оценщик независимо восстанавливает хеш пользовательского JSON и текст диапазонов из Git. Факт засчитывается при доставке **всех** его строк. У фрагмента вне цели нет ни одной опорной строки. Для старых отрицательных H учитываются также прежние разрешённые фоновые диапазоны. Неверная передача по отрицательному Q считается отдельно. Задержка группы — медиана по вопросам от медиан двух проходов, включая отказы. Время загрузки снимка, скоринг и генерация в неё не входят. [Драйвер](../../../tools/eval_m289_russian.py)

Для воспроизведения нужны исходное локальное окружение M289 и проверяемый launcher. Из корня проекта следует использовать новые имена выходных файлов.

```powershell
.\.venv\Scripts\python.exe -I -S -B tools/eval_m289_russian.py rank rank-local.json
.\.venv\Scripts\python.exe -I -S -B tools/eval_m289_russian.py context context-local.json --rank rank-local.json
.\.venv\Scripts\python.exe -B -m tools.eval_package_boundaries
```

## Почему замедлился N4

В отдельной серии из трёх парных проходов исходные варианты single и multi из предыдущего эксперимента дали прежние хеши JSON. Медиана single составила **1965 мс**, multi — **5623 мс**. Ранее были измерены 1920 и 5440 мс. Время засекалось внутри одного и того же вызова, интервалы поиска, штатной инспекции провайдера и экспериментальной упаковки не пересекаются.

| Измеренный этап, мс | single | multi |
|---|---:|---:|
| Поиск | 22,8 | 22,9 |
| Все инспекции провайдера за запрос | 1532,7 | 4792,0 |
| Экспериментальная упаковка | неприменимо | 3,9 |
| Остальное время запроса | 404,5 | 809,2 |

Медианы этапов подсчитаны по отдельности и могут не суммироваться до медианы всего запроса. В single инспектировалась только GitSourceReader._run. В multi медианы отдельных инспекций составили 1498 мс для неё, 1573 мс для GitSourceReader.capture и 1645 мс для scan_head. Прирост времени внутри инспектора (3259 мс) соответствует примерно 89% наблюдаемой разницы общих медиан (3658 мс). При каждом вызове исходный инспектор снова разбирает файлы переданного снимка и строит индекс символов. ScopedCandidates ограничивает допуск селектора, затем делегирует штатную инспекцию полного снимка. Остаток времени не разделялся на более мелкие операции. Замеры не дают основания считать упаковку главным источником регрессии. [Реализация инспекции](../../../modules/developer_task_ui/app/symbol_investigation.py#L547) · [Трассы трёх пар](rank.json)

## Доставка фактов и ложные совпадения

В ячейках порядок **A → B → C**. Доли попадания в top-k считаются по требуемым функциям каждого вопроса, а не по числу вопросов. Списки кандидатов B и C совпали для всех 38 вопросов.

| Функции в top-4 | 4 → 3 → 3 из 10 | 3 → 3 → 3 из 9 | 7 → 7 → 7 из 8 | 1 → 6 → 6 из 10 |

При 0/0 фрагментов доля не определена. Для H номера отрицательных и неоднозначных вопросов соответствуют прежней разметке; некоторые допускают полезное пояснение по статическим строкам. Пустая выдача прежде позволяла пропустить автоматическую инспекцию top-1; теперь число таких ранних выходов сократилось с семи до двух. На H2 доставлены все три факта о таймауте. При этом новый поиск вытеснил нужную функцию H4 с четвёртой позиции на шестую, а сборщик пропустил окна без эталонных строк для H1, H3, H4, H8, H9 и H10. На N3 и N5 лишние окна не добавили фактов. На P факты сохранились, хотя одно из попаданий в top-1 потеряно. Совпадение двух префиксов чувствительно к сообщениям для пользователя и плохо переносится на англоязычную реализацию либо вопросы о статистике. На трёх новых межфайловых связях остаётся ровно по одной неподтверждённой стороне.

## Проверки и вывод

Проверены варианты слов на синтетическом исходнике, совпадение вне области, запрос без опоры, отказ при единственном совпадении и сохранение отказа при явно запрошенном отсутствующем идентификаторе. Для обоих этапов прошли целевые проверки упаковки и 15 штатных проверок grounding. Обе выборки повторов дали идентичные списки, ссылки, факты и хеши запроса для каждой комбинации вопроса и варианта. Вариант A воспроизвёл все 28 прежних записей H/N/P. B воспроизвёл результаты первого этапа при повторном измерении на всех 38 вопросах. Полученные строки сверены с Git. Выходов за область и превышений бюджета не зарегистрировано; максимумы C — 1889 байт исходного текста и 3582 байта общего запроса. Проверки архитектурных границ — 32/32.

Основной критерий на этом Q достигнут: восемь ранее недоставленных фактов, три полностью обеспеченных однофайловых вопроса, три частично обеспеченных многофайловых. Эффект сопровождается ложными совпадениями и ростом задержки. Результат относится к доставке строк на этом Git-снимке. Качество генерации и публикации не измерялось.
