## Граница результата

- `call_sites` сообщает о найденных статических местах. Каждый такой claim содержит `call_site` с видом контекста, позицией вызова, координатой определения и ссылками на видимые основания. Строки нумеруются с единицы, смещения AST отсчитываются с нуля в байтах UTF-8, конец выражения исключён. У модульного места `caller=null`, `context_line` указывает на условие запуска. [Анализатор](../../../tools/skynet_call_sites.py)
- `call_coverage` содержит список обследованных файлов, поддерживаемые контексты, `project_exhaustive=false` и `execution_observed=false`. Поле проходит через автоматический выбор и составной ответ. `composed` и `completion_scope=requested_static_steps` описывают завершение выбранных статических операций. Полнота ответа относительно всего проекта из них не следует. [Объединение](../../../tools/skynet_compose.py)
- В блоке запуска поддержаны верхнеуровневый `if` с точным равенством имени строке `'__main__'` в любом порядке и прямые выражения в его теле, включая правую часть присваивания. Анализ пропускает ветвь `else`, вложенные инструкции управления, отложенные тела, вызовы через атрибуты и динамические ссылки. Уникальная привязка цели должна предшествовать условию. Консервативная проверка переприсваивания может скрыть реально достижимое место. Места из обычных функций по-прежнему разрешаются по правилам предыдущего читателя.

## Предложение следующего этапа для Cognitive Core

Предлагаем в следующем эксперименте сделать тонкий адаптер над существующим статическим читателем для `explain_code`. Владелец области и снимка — хост. Вопрос, ответ модели и интерфейс не могут добавить путь, Git-ревизию, команду или полномочие. Штатный профиль из трёх файлов и лабораторный из пяти выбираются раздельно. Адаптер можно проверить отдельно от Developer Tasks UI. [Действующие контракты](../../architecture/SKYNETVS_COGNITIVE_CORE_V2.md)

| Способность | Роль в адаптере | Что передавать и где провести границу |
|---|---|---|
| `calls` | Готова как базовая операция для однозначной функции | Проверенные места и вид контекста, координаты, основания, область, причина удержания. Пустой результат ограничен областью и поддерживаемым синтаксисом |
| `flow` | Готова как базовая операция для однозначного поля | Упорядоченные шаги, основания и статус `flow_limited` при обрыве. Условное чтение ключа форматировщиком сохранять как условное. Часть видов шагов пока выражена текстом |
| `auto` | Готова как внутренний маршрутизатор | Использовать маршрут, выбранную цель и запрос уточнения. Результат маршрутизации сам по себе не служит доказательством |
| `compose` | Готова как координатор нескольких операций | Сохранять `actions`, результаты шагов и `relations` по совпадающим координатам одного AST-вызова. Статус отдельно от полноты. При отсутствии связи передавать установленную границу |

Входом служит `TaskRequest`. Хост разрешает `source_id` в закреплённый снимок. Адаптер дедуплицирует проверенные фрагменты в `EvidenceSet.items` и переносит границы в `coverage/gaps`. Для `AnswerProposal` преобразует основания каждого утверждения в существующие `ref_id/lines`; решение о публикации остаётся у хоста. Отдельный новый контракт для четырёх CLI-флагов не требуется. Для первого среза достаточно двух прямых операций и существующего маршрута поверх них.

Критерий готовности адаптера — на новых входах воспроизвести условный вызов, многофайловый поток, частичный ответ и уточнение. Проверить отказ при неподходящем `source_id` и подмене ссылки, сохранность координат для двух вызовов на одной строке и отсутствие утверждения о факте запуска. Интеграция в production в этот checkpoint не входит.
