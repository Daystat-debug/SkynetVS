# Cognitive Core 0.7. Исследование по описанию поведения

В обычном запуске CLI пользователь может описать сообщение, уведомление или строку отчёта. Хост выбирает место в Git-снимке и глубину исследования. На втором зафиксированном наборе CLI дал восемь содержательных ответов на двенадцать разрешимых задач и корректно обработал шесть отрицательных. Ещё четыре разрешимые задачи потребовали уточнения. Лексический поиск дал столько же полных результатов и трижды опубликовал ответ о другом участке. Для отдельных запусков с локальной моделью цена проверки составила около восьми секунд.

## Как пользоваться

Из корня проекта в PowerShell:

```powershell
$py = '.\.venv\Scripts\python.exe'
& $py -I -S -B tools/skynet_investigate.py 'Когда в отчёт добавляется заголовок про локальный контекст и то, что код не выполнялся?'
& $py -I -S -B tools/skynet_investigate.py 'Кто непосредственно вызывает проверку с сообщением «M126_FILES_LIMIT», при каких условиях и какие аргументы передаёт?'
& $py -I -S -B tools/skynet_investigate.py --json 'Когда появляется «M134_REPORT_SCHEMA_INVALID»?'
& $py -I -S -B tools/skynet_investigate.py 'receipt_without_source@233'
```

В первом примере ядро находит `format_context`. Заголовок добавляется после проверки схемы отчёта, когда в `_private_8k_text` есть непустое значение. Во втором ядро устанавливает владельца диагностики, запрашивает его вызывающие участки, связывает `old_sources` с `before_files`, показывает `top_n=10` и проверяет условия в обеих функциях. Для точной цитаты модель не требуется. В третьем примере одинаковая диагностика записана в двух местах. CLI показывает оба со ссылками; последняя команда проверяет условия выбранного варианта. [Заголовок](https://github.com/Daystat-debug/SkynetVS/blob/fb30428c94b3d477dde9b5e081435a1669822aad/modules/developer_task_ui/app/context_search.py#L222-L226) · [Передача аргументов](https://github.com/Daystat-debug/SkynetVS/blob/fb30428c94b3d477dde9b5e081435a1669822aad/modules/developer_task_ui/app/retrieval/m130_rank.py#L110-L116) · [Проверки получателя](https://github.com/Daystat-debug/SkynetVS/blob/fb30428c94b3d477dde9b5e081435a1669822aad/modules/developer_task_ui/app/retrieval/m126_rank.py#L34-L45)

## Выбор цели и доказательств

Хост строит каталог из выражений разрешённых функций верхнего уровня. Запись содержит исходную строку, владельца и ближайшее условие для поиска. Индекс включает строковые аргументы, диагностики и подписи, в том числе f-строки. Комментарии не становятся наблюдаемыми действиями. Поддерживаются вопросы о месте, условиях и одном непосредственно вызывающем участке. Именованные запросы о связях, полях и аргументах используют существующие инструменты. Явные режимы `--why` и `--research` доступны отдельно. [Вход CLI](../../../tools/skynet_investigate.py) · [Выбор цели](../../../tools/skynet_observation_goal.py) · [Сборка доказательств](../../../tools/skynet_observed_route.py)

Для уникальной цитаты хост использует привязанную к AST запись. Для пересказа хост распознаёт тип вопроса, ранжирует карточки по тексту и даёт локальной Qwen выбрать один номер либо воздержаться. Для публикации нужны согласие с первым лексическим кандидатом и хотя бы одна общая с вопросом основа слова, отличительная для самой подписи в каталоге. Это ограничивает ложные совпадения и отсекает часть синонимичных пересказов. Модель не выдаёт путей, инструментальных команд, утверждений или ссылок для публикации.

После выбора цели хост выполняет только нужные действия. Вопрос о месте требует исходного выражения; вопрос об условиях добавляет локальное доказательство. Для вызывающего участка нужны проверенный вызов, привязка параметров и условия у обеих сторон. Достигнутый предел помечается в ответе. Перечисленные условия относятся к нормальному вычислению выражений. Совместная выполнимость всех условий на конкретных данных и факт запуска остаются открытыми.

Область доступа по-прежнему состоит из пяти файлов Git HEAD. Действуют шесть инструментальных шагов, 96 элементов доказательств и дедлайн 25 секунд. В ветке поиска по наблюдениям каталог ограничен 256 записями, сериализованный список вариантов для модели — 8400 байт без вопроса и системной инструкции. Хост проверяет координаты, Git blob, хеши, выданные ссылки и актуальность HEAD. Содержимое исследуемых файлов не исполняется.

## Что показали сравнения

В первом эксперименте фиксировали совместный выбор источника и действия. На 21 новом вопросе (16 проектных, 5 в одноразовом Git-снимке) Core 0.6 дал 7 полных результатов с учётом отказов. Поиск по тексту дал 13, из них 6 корректных отказов, и выпустил ещё 4 ответа о чужих местах. Модель, обязанная указать и номер, и операцию, дала 7 полных результатов, все отказы. Её 17 предложений не прошли проверку формата или смысла операции. Гибрид с быстрым путём дал 9/21. Во время разработки на вопрос о подсказке уточнить технические термины модель также запросила уточнение; при инструментированном повторе она вернула номер другой диагностики и операцию `clarify`. [Вопросы и эталоны](transfer.json) · [Результаты, сырые ответы и время](results.json)

После этого сузили выход модели до одного номера. Для нового сравнения зафиксировали другие вопросы, новый синтетический сюжет и рубрику по исходникам до первого предъявления. Первый набор не использовался для оценки второй версии. В обоих экспериментах вопросы не содержат имён функций. Часть задач даёт фрагмент сообщения или код диагностики. Часть участков реального проекта знакома по прошлым этапам. Независимость здесь относится к вопросам второго сравнения и новым сгенерированным объектам. На реальной части второй проверки итоговый результат — **9/12**: пять содержательных ответов, четыре правильных отказа и три нерешённые задачи. В синтетической части — **5/6**: три содержательных ответа, два правильных отказа и одна нерешённая задача. На G02 ядро само нашло вызывающую функцию без имени в вопросе, установило фактический аргумент `depth=25` и доказало, что условие `depth >= 26` исключает отложенную проверку на этом вызове. Для восьми содержательных ответов проверены 65 появлений Git-ссылок. Эталоны отдельно проверяют смысл условия, требуемые участки, привязку аргументов и результат. Неверных мест или необоснованных утверждений о выполнении среди этих ответов при сверке не выявлено.

**Ошибки и уточнения.** T01 и T02 остались без надёжного выбора строки даже внутри одного отчёта. В T07 система не связала пересказ о росте размера текста с проверкой бюджета отображения. В G01 не распознала пересказ перемещения копии в карантинную папку. Исследовательский вариант предложил шесть ошибочных ориентиров как подсказки, включая два вопроса, для которых в снимке вообще нет источника. В выпускаемой CLI при таком расхождении выдаётся просьба уточнить признак. Сохранены варианты для двух действительно неоднозначных дословных фрагментов. Повтор с теми же 18 вопросами и теми же решениями модели подтвердил, что удалены только шесть подсказок; содержательные ответы, отказы, шаги и ссылки на выданные факты совпали.

**Прежние T05/T06/T08.** Без дополнительных шагов ядро доказывает вычисление обычного аргумента вложенного вызова и вычисление вызова, образующего сам тест `if`. В T05 набраны 13/13 пунктов исходной рубрики, в T06 — 18/18. Короткое замыкание, генераторы и условные выражения остаются за границей этого правила. На T08 найдены три перехода и место диагностики. За шесть шагов получены 14/29 пунктов вместо нуля у 0.6. Ответ явно частичный, условия всего маршрута не доказаны. Исторический режим воспроизводит исходные показатели.

**Стоимость.** Основные замеры включают работу хоста с открытым снимком и запрос к уже загруженной Qwen3-8B, когда он потребовался. Порядок вариантов чередовался. Три холодных запуска сервера во втором эксперименте заняли 5,8–8,4 с. Полный запуск CLI на T04 с моделью занял 8,09 и 8,08 с. Межфайловой задаче T05 с точной цитатой потребовалось 0,78 и 0,97 с. Проверены также выдача двух координат и последующий запрос по выбранной координате. Всего выполнено **73 локальные генерации**: 32 в первом сравнении, 37 во втором, две разработческие и две в замерах CLI. Повторы статических доказательств использовали сохранённые решения. ## Воспроизведение

```powershell
$py = '.\.venv\Scripts\python.exe'
& $py -I -S -B tools/test_observation_goal.py
& $py -I -S -B tools/eval_observation_goals.py verify
& $py -I -S -B tools/eval_observation_goals.py verify --separate --delivery
& $py -I -S -B tools/eval_observation_goals.py verify --separate --lexical-control
& $py -I -S -B tools/eval_route_research.py verify
```

Оценщик берёт вопросы из коммитов заморозки, читает Git-объекты в одноразовой копии и сверяет идентичность вопроса и меню по SHA-256 до повторного использования решения модели. Проверены подмена ссылки, смена HEAD и исчерпание бюджета. Для отдельного живого замера с установленной локальной моделью передайте свободное имя файла. Эта команда выполнит дополнительные генерации:

```powershell
& $py -I -S -B tools/eval_observation_goals.py record --separate --output (Join-Path $env:TEMP ('core07-' + [guid]::NewGuid() + '.json'))
```
