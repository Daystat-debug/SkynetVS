# Первый headless-адаптер Cognitive Core V2

Хост принимает русский вопрос. На закреплённом Git-снимке он запускает существующий статический читатель, передаёт координатору доказательства и принимает решение о публикации. Для составного вопроса K1 он нашёл вызов ранжировщика, проследил поле между M127 и M130 и выдал четыре утверждения с девятью проверенными фрагментами. Для K3 трасса оборвалась на переменной `additions`, и хост удержал ответ. [Полные результаты всех шести вопросов](results.json)

## Запуск

Из корня SkynetVS на Windows, с проектным Python и проверяемым комплектом M289:

```powershell
.\.venv\Scripts\python.exe -I -S -B tools/skynet_core_explain.py "Где вызывают rank_symbols и как формируется function_candidates_total?"
.\.venv\Scripts\python.exe -I -S -B tools/skynet_core_explain.py --json "Как формируется query_expansion?"
.\.venv\Scripts\python.exe -I -S -B tools/test_core_task.py
.\.venv\Scripts\python.exe -I -S -B tools/eval_core_adapter.py verify
```

Обычный вывод предназначен пользователю. JSON содержит запись задачи, принятые контракты, действительно переданные `ref_id` и оценку хоста. При отклонённом предложении или отмене запись содержит состояние, этап и причину. Сырое отклонённое предложение в неё не попадает. Диагностический JSON при `insufficient` сохраняет частичные наблюдения в доказательствах; список публикуемых утверждений пуст.

## Как проходит один запрос

1. Хост создаёт `TaskRequest` с новым ID и видом `explain_code`. Логический источник `skynetvs.retrieval` привязан политикой лабораторного хоста к пяти разрешённым файлам снимка `ee908b063c31a5c9dd8e97ef64ca2ddc3b423235`. Вариант хоста с тремя файлами использует собственную привязку. Вопрос не выбирает пути, ревизию или более широкий профиль. Проверяются идентификатор, SHA и точное множество путей. Используется прежний транспорт чтения Git-объектов; анализируемые модули не импортируются.
2. Адаптер вызывает Python-вход `compose`. Для одиночного вопроса он делегирует выбор `auto`; для составного — вызывает нужные `calls` и `flow`. Из возвращённых структур адаптер строит `EvidenceSet`: исходные строки, проверенные координаты, область и причины пробелов. Пересекающиеся утверждения могут ссылаться на один и тот же `ref_id`. Git-путь, commit, blob, URL, диапазон, хеш фрагмента и текст сверяются с одним снимком.
3. Экспериментальные аннотации в **необязательном** поле `EvidenceSet.analysis` содержат операции, наблюдения с привязкой к элементам, места вызова и отношения. Для связи вызова с потоком хранится результат уже существующего сопоставления одного AST-выражения и ID оснований для вызова и определения. Это детализация конкретного Git-адаптера. Минимальные поля трёх контрактов сохранены; координатор работает и с набором без `analysis`.
4. Детерминированный provider получает отдельную копию набора и возвращает `AnswerProposal`. При неполной трассе возвращает `insufficient`; при пустом наборе координатор пропускает provider. Хост допускает только исходные пары «утверждение — его основания» и только выданные диапазоны. Статический provider не получает Git-читатель или право публикации.
5. `Task` проверяет отмену и 30-секундный дедлайн между шагами и под блокировкой перед выдачей. Первое терминальное решение сохраняется. Встраивающий хост может вызвать `task.cancel(task.request.task_id)`; CLI обрабатывает прерывание с клавиатуры. Начатая синхронная операция может завершиться позже отмены. Её результат подавляется.

## Что установлено

| Вопрос | Итог | Передано фрагментов |
|---|---|---:|
| K1. Вызов `rank_symbols` и происхождение `function_candidates_total` | Ответ. `rank` получает `sym`; `sym['symbol_candidates']` восходит к `len(rows)`. Один установленный статический переход | 9 |
| K2. Кто вызывает `rank_title_only` | Ответ. `rank` сохраняет результат в `files`. В блоке запуска M126 результат попадает в `result`, если выполнение дойдёт до строки | 6 |
| K3. Происхождение `query_expansion` | Неполная трасса. Установлен второй элемент возврата `expand_query`, единственный источник `additions` до чтения не установлен | 4 |
| K4. «Откуда берётся число кандидатов?» | Уточнение с выбором между файлами, функциями и модульными участками | 0 |
| K5. Поиск вызова в `main.py` | Источник вне области | 0 |
| K6. Число файлов в последнем запуске | Требуются данные о запуске | 0 |

Ссылки K1 проверены по [M130](https://github.com/Daystat-debug/SkynetVS/blob/ee908b063c31a5c9dd8e97ef64ca2ddc3b423235/modules/developer_task_ui/app/retrieval/m130_rank.py#L125-L135) и [M127](https://github.com/Daystat-debug/SkynetVS/blob/ee908b063c31a5c9dd8e97ef64ca2ddc3b423235/modules/developer_task_ui/app/retrieval/m127_symbol.py#L87-L108). Условный вызов K2 виден в [блоке запуска M126](https://github.com/Daystat-debug/SkynetVS/blob/ee908b063c31a5c9dd8e97ef64ca2ddc3b423235/modules/developer_task_ui/app/retrieval/m126_rank.py#L93-L104).

Для **подлинности** хост сверяет точные фрагменты. Для **связи** ядро получает вид статического вывода, координаты и основания. **Полнота** успешного ответа остаётся отдельно не оценённой; у оборванной трассы записано `partial`. **Выполнение** ни в одном случае не наблюдалось. `coverage=partial` характеризует синтаксическое подмножество даже при чтении всех разрешённых файлов. Решение `answered` даёт право показать конкретные утверждения в этих границах.

## Ошибки и проверки

- В первой итерации на `eb7c950` тестовый provider сохранил ссылку на возвращённый словарь. Контрольная замена текста после проверки попала в опубликованный результат: `state=answered, published_after_mutation=True`. Во второй итерации хост отделил данные предложения до проверки. Тест `detached_provider_result` воспроизводит то же вмешательство и проверяет сохранение проверенного текста.
- Подмена Git URL отклонена при сборе доказательств. Чужая подлинная ссылка и неизвестный `ref_id` отклонены на проверке предложения. Неподходящий `source_id` отвергнут до открытия источника. Проверены более широкий снимок для ограниченного хоста и реальная работа на трёх файлах, отмена до чтения и во время provider, дедлайн непосредственно перед публикацией. Все **10/10** контрольных сценариев дали ожидаемый исход.
- При первом сравнении сохранённого и живого результата K4 тест обнаружил различие типов: варианты уточнения были Python-кортежами, JSON возвращает массивы. Исправлено сравнение сериализованного контракта. Сохранённая выдача и эталон вопроса не изменялись. Все шесть результатов независимо воспроизведены отдельными процессами в обоих режимах вывода.
- Сохранились **38/38** архивных решений, **14/14** пар предыдущего сравнения и **32/32** архитектурных проверок. Координатор отдельно проверен с портами в памяти без Git, UI и модели. [Рубрика до реализации](questions.json) · [Журнал проверок](checks.txt)

Это экспериментальный статический provider. Он умеет переносить уже установленные инструментами факты. Новые разновидности Python-связей, продолжение диалога после уточнения и независимая смысловая оценка остаются вне этого среза. Проверки рассчитаны на доверенные компоненты в одном процессе. Бюджет — две существенные итерации, ноль генераций Qwen.
