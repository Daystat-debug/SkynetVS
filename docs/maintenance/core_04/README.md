# Cognitive Core 0.4 — от сообщения об ошибке до участка кода

Разработчик может вставить строку исключения или спросить по-русски, при каком условии код выдаёт сообщение. Если он укажет входную функцию, ядро попробует показать один статический путь от неё до инструкции `raise`. Имя функции с этой инструкцией ядро устанавливает по снимку. CLI работает на Windows с прежним локальным комплектом M289.

```powershell
$py = '.\.venv\Scripts\python.exe'
& $py -I -S -B tools/skynet_investigate.py 'Как из search_repository дойти до ошибки M127_SYMBOL_LIMIT?'
& $py -I -S -B tools/skynet_investigate.py 'ValueError: M127_TOP_LIMIT_INVALID'
& $py -I -S -B tools/eval_diagnostic_path.py verify
```

В первом примере ядро нашло три прямых вызова: `search_repository → rank → rank_symbols → extract_symbols`. В последней функции записан `raise ValueError('M127_SYMBOL_LIMIT')`, если в списке `out` больше 3 500 элементов. Во втором примере достаточно одного просмотра AST. Условие в `rank_symbols` отклоняет `limit`, если проверка на `int` ложна, значение меньше 1 или больше 100. Добавьте `--json` для получения инструментальных шагов, утверждений, SHA снимка и ссылок. ## Как выбирается следующий шаг

В 0.3 для поиска пути обычно требовалось назвать обе функции. Теперь первая операция ищет строковый аргумент явного `raise` в функциях верхнего уровня. Допускается точный текст или код до двоеточия. Для вставленной строки исключения проверяется также написанное в исходнике имя конструктора. Совпадение в комментарии или обычной строке вывода не образует свидетельства.

Когда вход не задан и найден один поддерживаемый участок, выдаются его условие и строки. Если участков несколько, ядро просит указать вход. При известном входе оно рассматривает все найденные окончания пути. Наблюдение `calls` добавляет в очередь проверенных вызывающих. До углубления в одну ветвь проверяются соседние варианты, уже обследованные цели переиспользуются. Для R06 один и тот же код записан в двух функциях. От `rank` доказан короткий путь через `module_rank`; связь с `modules_from_source` для этого ответа не понадобилась. [Места с одинаковой диагностикой](https://github.com/Daystat-debug/SkynetVS/blob/dc7000c6ce693964e551c9af16f5d710c286c9ec/modules/developer_task_ui/app/retrieval/m130_rank.py#L60-L72) · [Поиск](../../../tools/skynet_diagnostic_path.py) · [Интеграция в хост](../../../tools/skynet_investigate.py)

## Неудачи и границы вывода

На реальном коде 0.4 полностью решил **8 из 10** положительных задач и дал ожидаемую причину удержания в **6 из 7** отрицательных. На графах — **5/6** и **12/12**. Ни по одной из 19 отрицательных задач ответ с утверждениями не опубликован. В опубликованных ответах 0.4 проверено 89 появлений ссылок по байтам Git. Ссылка удостоверяет текст места. Статическая цепочка удостоверяет отдельные выражения вызовов. Для конкретного входа условие может оказаться ложным, а исключение может быть перехвачено.

- **R05** — общее уточнение вместо указания, что у сообщения два источника. Разбор фразы «откуда берётся» остановился ещё до AST.
- **R09** — место исключения найдено, но на вопрос «почему» дан частичный ответ. В `find_git` подходящий кандидат приводит к более раннему `return`. Для полного объяснения нужен анализ выхода из предшествующего цикла. Статус `answered` для одного найденного места сам по себе не гарантирует полноту объяснения. [Цикл и выход](https://github.com/Daystat-debug/SkynetVS/blob/dc7000c6ce693964e551c9af16f5d710c286c9ec/modules/developer_task_ui/app/git_source.py#L35-L39)
- **R14** — разговорное «На что именно ругается код?» привело к запросу уточнения.
- **G13** — глубокий путь остался за лимитом. Ядро явно сообщило об исчерпании шагов. Подтверждены только поддерживаемые статические вызовы и локальные ветви. Методы, динамические сообщения и произвольные конструкции Python требуют отдельных способов проверки.

## Воспроизводимость

`eval_diagnostic_path.py verify` повторяет сравнение с закреплёнными вопросами и сверяет решения, тексты, координаты и отказы. Время измеряется заново. Каждый локатор независимо проверяется по commit, blob, SHA-256 файла и отрывка, диапазону и URL. Коммиты синтетических снимков воспроизводятся в одноразовой копии. Дополнительно проверены подмена ссылки, подмена цели другим действительным определением, смена HEAD и исчерпание бюджета.

Исторические `verify` воспроизвели Core 0.1 — 15/15, Core 0.2 — 26/27 с прежним T5, Core 0.3 — 8/9, 14/14 и 9/9. Пройдены 38/38 архивных решений статических инструментов, 14/14 пар профилей, шесть заданий адаптера и десять контролей публикации, доступа и отмены, 11 проверок обзора изменений и 32 проверки пакетных границ. Полный production pipeline в эту проверку не входил.
