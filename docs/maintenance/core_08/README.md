# SkynetVS Cognitive Core 0.8

Экспериментальный CLI теперь может по признакам двух функций самостоятельно найти прямой вызов, установить его направление и показать основания в обоих файлах. На заключительном наборе он правильно закрыл 9 из 16 задач против 4 у выпущенного Core 0.7. В эти девять входят четыре содержательных ответа и пять обоснованных отказов. На семи разрешимых вопросах без дословной подсказки получен один полный ответ. Та же локальная интерпретация с простым поиском по объединению слов дала идентичные утверждения во всех 16 случаях. Преимущество обязательных смысловых признаков перед этой альтернативой не установлено. Новый режим оставлен экспериментальным.

## Запуск

Из корня репозитория в PowerShell. Первая команда при необходимости обращается к уже установленной локальной Qwen. Вторая проверяет связь приведённых признаков через индекс и статические вызовы без генерации.

```powershell
$py = '.\.venv\Scripts\python.exe'
& $py -I -S -B tools/skynet_investigate.py --explore 'Функции с сообщениями «M127_TITLE_INVALID» и «M130_NO_SCOPE_FILES_WITHIN_LIMIT» напрямую вызывают одна другую? Покажи свидетельство.'
& $py -I -S -B tools/skynet_investigate.py --indexed 'Есть ли вызов между «M134_GIT_PROJECT_ROOT_MISMATCH» и «M134_NO_LEXICAL_MATCH»?'
& $py -I -S -B tools/eval_source_language.py verify --final
& $py -I -S -B tools/eval_source_language.py guards
```

Для структурированного ответа добавьте `--json`. CLI без новых флагов сохраняет режим 0.7. Архивный оценщик работает с закреплёнными Git-объектами и ответами интерпретатора. Синтетические коммиты воспроизводятся во временной копии. Их диапазоны строк проверяются локально. Реальный вопрос в CLI исследуется на текущем Git HEAD.

## Что изменилось

В 0.7 все цитаты должны были совпасть в одной карточке. Теперь два ориентира могут задать цель «существует ли прямой вызов между содержащими их функциями». Если поиск входящих вызовов с первой стороны не дал свидетельства, ядро проверяет вторую. Для направленной задачи допустимо только запрошенное направление. При обнаружении связи публикуются обе исходные строки и проверенное место вызова с импортом, когда он необходим. На C06 первый запрос мест вызова не дал результата, второй установил вызов `scan_head` из `search_repository` на строке 150. В C05 сначала проверена функция `rank`, затем найдена привязка вызова `rank_symbols` к импорту из соседнего файла. Эти свидетельства относятся к телам функций. Оба диагностических сообщения могут находиться на ветвях, исключающих их совместное появление. [C06, исходник](https://github.com/Daystat-debug/SkynetVS/blob/2d69cbfe0d74d2419dabe818b9b932fbfc53e623/modules/developer_task_ui/app/context_search.py#L144-L156) · [C05, вызов](https://github.com/Daystat-debug/SkynetVS/blob/2d69cbfe0d74d2419dabe818b9b932fbfc53e623/modules/developer_task_ui/app/retrieval/m130_rank.py#L110-L126) · [C05, вторая функция](https://github.com/Daystat-debug/SkynetVS/blob/2d69cbfe0d74d2419dabe818b9b932fbfc53e623/modules/developer_task_ui/app/retrieval/m127_symbol.py#L72-L76)

Для поиска по пересказу использованы 68 русских описаний выражений, 44 автоматически извлечённых соответствия для элементов идентификаторов и 48 формулировок четырёх видов запроса. Входом при подготовке служили разрешённые исходники и описания операций. Вопросы из трёх новых наборов к этому моменту ещё не были составлены. Описание привязано к хешу имени владельца, вида инструкции, выражения и его локального условия. Для изменённого описателя доступна лексика текущего кода. Существующий обучаемый NLU классифицирует команды по меткам интентов из `data/intents.json`. Его выход не содержит цели в коде или обязательств по доказательству, поэтому веса и обучающие данные этого компонента оставлены в прежнем виде. [Построение индекса](../../../tools/build_observation_language.py) · [Поиск](../../../tools/skynet_source_language.py) · [Существующий NLU](../../../train/train_nlu.py)

При затруднении в новом режиме локальный интерпретатор получает только вопрос и типы операций. Хост принимает ограниченное описание предмета и отличительного признака, затем самостоятельно выбирает место в разрешённом AST. В заключительном варианте для каждого признака нужна отдельная опора в словах владельца, выражения или условия. Русские описания помогают первоначальному поиску. Модель не выбирает файл для чтения, URL или утверждение для публикации. Тексты и ссылки строятся прежними инструментами на снимке хоста. Остались пять файлов, шесть шагов, до 96 элементов доказательств и 25 секунд. Граница анализа включает поддерживаемые выражения уникальных функций верхнего уровня. ## Три последовательные проверки

Для каждого сравнения сначала зафиксирована реализация, затем вопросы и построчная рубрика. Реальный снимок во всех трёх сравнениях — `2d69cbf`. Для каждого переноса создан отдельный синтетический Git-объект в прежней области доступа. Порядок вариантов чередовался. Рубрика проверяет цель вместе с видом действия, текст утверждения, обязательные строки, направление вызова, привязку аргументов и полярность условий, когда они запрошены. Независимая проверка ссылок сверяет commit, blob, SHA-256 источника и отрывка, диапазон и URL. Голос модели в оценке качества не используется.

На новом коде F12 и F14 модель, которой показали каталог, находила ответ там, где перевод вопроса воздерживался. Полнота доказательств означает наличие всех пунктов рубрики. Для вопроса о месте достаточно точной строки и определения владельца. Корректность заключения оценивается по опубликованному тексту. Последний вариант выполнил 46 инструментальных шагов на 16 задачах, максимум пять на вопрос. Проведены девять парных интерпретаций для двух способов поиска. Ответы модели совпали в каждой паре. Наборы вопросов авторские, часть функций повторяется между срезами. Утверждения о переносе на новый код относятся к трём ранее не использованным синтетическим дополнениям внутри профиля. - **F24.** По вопросу «Где подтверждается готовность начинать запись?» в новом англоязычном коде найдена строка `Recording ready to begin` в `capture_status`. Обе стратегии поиска по переводу доставили её с правильными ссылками. На остальных трёх положительных пересказах без цитат в новом видеокоде этот режим воздержался.
- **C03.** Место лексического отказа и его условие установлены правильно. На «Где прерывают поиск, если…» ядро выбрало объяснение условий. По предварительной рубрике это ошибка вида ответа. **C04.** Ошибка существеннее: на вопрос об условиях возвращено только место диагностики. Хост присвоил ответу статус `answered`. Это известный случай неполного ответа с подлинными ссылками.
- **C02 и F21.** Интерпретатор добавил в JSON лишние поля. **F22.** Вместо условий выбрано место. **F23.** Для одной цели пришли два операнда. Хост воздержался. **C01.** Существующий языковой фильтр реагирует на начало слова «исправность» так же, как на просьбу о правке. Требование уточнения в этих случаях учитывается как пропуск.
- **C07, C08, C09, F26, F27.** Удержаны ответ про подпись бухгалтерии, вывод о прошлом запуске, обращение к стороннему пути, прогноз времени съёмки и утверждение о неустановленной прямой связи. В F27 выполнились обе проверки входящих вызовов. Глобального отсутствия пути это не доказывает.

### Стоимость и воспроизводимость

Медианы в заключительной таблице измерены на открытом Git-снимке, включая генерацию при уже загруженной модели. Чтение реального и синтетического снимков заняло 314 и 297 мс. Три запуска сервера в этом сравнении заняли 7,69–8,33 с. Для девяти запросов нового режима измерены 1765 входных и 404 выходных токена, суммарно 3,52 с работы провайдера. При холодном пользовательском запуске C05 занял **10,09 с**, C06 с детерминированным выбором — **0,74 с**. Для C05 прежний CLI за 0,69 с попросил уточнение. Замеры относятся к этому компьютеру. Телеметрии энергии нет. [Холодные запуски CLI](cold_cli.json)

На построение индексов затрачено 18 генераций, 5343 входных и 2974 выходных токена, 24,31 с ответов провайдера плюс два запуска. Три разработческие генерации на постороннем вопросе о терминале сохранили две неудачные формы JSON и одну принятую. В трёх завершённых сравнениях зафиксированы **9 + 45 + 32 = 86** генераций. Холодные запуски добавили две. Итого документированы 109 вызовов. Ещё один прерванный прогон второго набора потерял счётчик процесса. По порядку вариантов до воспроизведённого сбоя F11/site восстанавливаются ещё 26 вызовов. Суммарный расход около 135, точное значение для потерянного прогона не подтверждено. Отдельный повтор дал медиану 126 мс для работы хоста с готовым ответом интерпретатора у варианта с группами. Первый и заключительный наборы измерены целиком вживую. Практически подтверждены статический поиск связи по двум ориентирам и отдельные случаи межъязыкового поиска. Открытая задача — выбор обязательного вида доказательства, особенно различение места и условий. Для следующего исследования полезно проверять эту способность отдельно от выбора строки на парных вопросах об одном и том же фрагменте. Это позволило бы увидеть случаи вроде C04 до публикации ответа.
