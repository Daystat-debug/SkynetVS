# Cognitive Core 0.12. Перенос опыта на новые задачи

На основной выборке обучение на дополнительных 16 задачах снизило число содержательных решений с 9 до 7 из 20. На соседних предметных областях получен небольшой выигрыш, который воспроизвело простое правило выбора инструмента. Свидетельств устойчивого улучшения на незнакомых сочетаниях требований нет. Версия 0.12 доступна для явного запуска в лабораторном CLI. Вызов без номера версии сохраняет историческое поведение.

## Как устроен локальный цикл

1. Источник обратной связи — закреплённая в Git рубрика с исходной просьбой, типами фактов, целями, строками, предикатами и допустимыми основаниями отказа. Для каждой задачи три стратегии независимо исследуют один снимок. Оценщик сверяет доставленные утверждения с рубрикой, проверяет Git-ссылки и сохраняет удачные и ошибочные решения. Клиентский вопрос, мнение Qwen или статус `answered` сами по себе не создают обучающей метки. Цикл работает офлайн и требует проверенной человеком рубрики.
2. Первая стратегия использует память Core 0.11, вторая — прежний лексический выбор. Третья объединяет сигналы памяти и лексики. Она может использовать тип предыдущей просьбы в коротком продолжении и объединяет одинаковые цитированные цели. Запросы об общем объекте получают ссылки на одни и те же типизированные факты. Новые чтения проходят через прежние сборщики и хост. В одном пользовательском запуске выполняется одна выбранная стратегия.
3. Первый обучаемый вариант подбирает небольшое дерево по результатам **целых ответов**. Полное решение даёт 5 баллов, полезное частичное с распознанными причинами — 4, с обозначенным пробелом — 2, правильно объяснённый отказ — 1. Ложная полнота или выбор постороннего участка дают −6. Признаки описывают структуру вопроса, наличие ориентиров и разногласия способов интерпретации. Объектов исходного кода и идентификаторов задач в дереве нет.
4. Второй вариант учится исправлять **набор видов доказательств** для каждого отрезка. Для каждого типа он обновляет линейные веса по ошибке относительно человеческой разметки. Вход включает исходное предположение, предыдущее требование, связь с целью и частотные русские основы. Для прежних ложных полных ответов допускается большая поправка. Известные примеры не добавляются в текст вопроса. Веса определяют запрос к инструментам; публикация использует действительные проверенные свидетельства. Шесть проходов, фиксированный порядок перемешивания и округление дают воспроизводимые веса. Нулевая, начальная и обновлённая модели имеют общий алгоритм вывода.
5. Начальный опыт — 8 реальных задач серии Core 0.11. Новый пакет — ещё 16 прежних задач на двух синтетических программах. Калибровка выбирает глубину дерева из 0–2 и порог для линейной поправки. Параметры сравнения до и после общие. Для 24 задач сохранены 72 исследовательских ответа, включая ошибки. Обучение потребляет только закреплённые материалы. ## Разбиение

В предварительной серии ручной просмотр выявил сходный вопрос о двух ветвях условия в опыте и калибровке. Её материалы доступны в коммите `32c80b6`: три глубины получили 31, 26 и 20 баллов, был выбран постоянный способ. До запуска на контроле введено более строгое правило. Для основной серии множества комбинаций типов с учётом кратности попарно не пересекаются между обучением, калибровкой и контролем. Например, две просьбы найти прямых вызывающих относятся к одной комбинации независимо от объектов и формулировок. Проверяются также раздельность исходных инцидентов и близость вопросов после маскирования цитат. Родственные варианты A1/A2 и B2/B3 оставлены в одной контрольной выборке и дополнительно оцениваются парами.

Окончательная калибровка включает 8 задач ткацкого производства. Дерево получило 13, 13 и 14 баллов в зависимости от глубины, линейная поправка — максимум 11. Выбор на один балл оказался хрупким. По первым 8 задачам дерево всегда выбирает память. После накопления 24 задач оно выбирает лексику без цитаты, память с одной цитатой, сбор общих доказательств с несколькими. Выбор закреплён в `f3d2ac1` **до составления** основного контроля `c2dec15`. Политики и веса после измерений сохранены. [Калибровка](grouped_calibration.json) · [20 вопросов, рубрики, пары и три новые программы](grouped_transfer.json)

Разделение по комбинациям относится к новому циклу 0.12. Все предшествующие способы сохранены вместе с их исходными обучающими материалами. В реальной части встречается ранее исследованная функция `expand_query`. Поэтому отдельно приведены результаты на полностью новых синтетических программах. Все выборки авторские. Вторичная серия из 24 вопросов по другим предметным областям допускает знакомые комбинации и служит отдельной проверкой переноса. [Вторичная рубрика](transfer.json)

На архивном наборе из 16 вопросов Core 0.10 дерево перешло с 4/5 и одной ложной публикации к 5/5 и нулю. Этот последний прогон показывает сохранение ранее известных способностей; он не является независимым измерением. ## Успех и граница

- **R5.** По одному вопросу хост показал два разных прямых вызова, включая межфайловой импорт: `rank → rank_symbols` и `search_repository → expand_query`. Это подтверждается реальным запуском CLI и строками в Git. На этой задаче ранняя политика также дала полный ответ.
- **A1/A2.** В просьбе о двух вызывающих функция A1 описывает насос и манометр без цитат. Обновлённая политика выбрала прежний лексический план, привязавший обе просьбы к насосу. Она объявила ответ полным, хотя ни одного свидетельства о ремонте манометра не предъявила. С явными цитатами вариант A2 дал правильные две связи. A4 потерял доказательство аргумента при переходе на лексику. В C2 общий сбор не разобрал два ориентира внутри частей и потерял полный ответ ранней политики.
- **A3.** Появился полезный частичный ответ об участке программы и его вызывающем коде, но система не объяснила достаточно точно, почему для длительности реального наполнения нужны наблюдения. Ни один из пяти частичных ответов выпущенной политики не прошёл строгую проверку причин всех пробелов.
- Выигрыш на нескольких знакомых формах задач не подтверждает перенос на новые сочетания. На данном материале дерево научилось выбирать способ по кавычкам. У него нет представления, которое доказывало бы, относятся ли две просьбы к одному объекту. Подтверждённая ссылка осталась применима к своему участку и после того, как исследователь ошибочно использовал её для другой части запроса.

## Воспроизведение из корня проекта

```powershell
$py = '.\.venv\Scripts\python.exe'
& $py -I -S -B tools/build_experience_policy.py --verify
& $py -I -S -B tools/test_experience.py
& $py -I -S -B tools/eval_experience.py verify
& $py -I -S -B tools/eval_experience.py verify --domains
& $py -I -S -B tools/eval_experience.py verify --retention
& $py -I -S -B tools/eval_experience.py summary
& $py -I -S -B tools/skynet_investigate.py --requirements --requirements-version 0.12 'Кто непосредственно вызывает проверку с «M127_TITLE_INVALID» и кто обращается к обработчику «M134_GOAL_EMPTY_OR_TOO_LONG»?'
```

`build_experience_policy.py --verify` заново получает результаты из изолированных Git-снимков, обучает модели и сравнивает их и обучающий журнал с сохранёнными артефактами. Без флага скрипт записывает экспериментальные артефакты по их штатным путям. `verify` для измерений заново строит доказательства и проверяет совпадение конечных ответов, оценок и хешей запросов к модели. Новый живой замер выполняется командой `record --file НОВЫЙ_ФАЙЛ.json`. В основной серии было 54 генерации Qwen у предшественников, во вторичной — 65, в цикле обучения и работе 0.12 — 0. Медианы измерены на открытом снимке со сменой порядка стратегий. В сумме основной серии 0.12 выполнил 68 действий против 66 у ранней политики. Полномочия и пять разрешённых файлов прежние.
