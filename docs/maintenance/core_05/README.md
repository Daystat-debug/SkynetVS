# Cognitive Core 0.5 — при каких условиях достигается строка

Хост исследует одну инструкцию внутри функции верхнего уровня на Git HEAD. Её можно выбрать по диагностике или как `имя_функции@номер_строки`. На Windows из корня проекта с локальным комплектом M289:

```powershell
$py = '.\.venv\Scripts\python.exe'
& $py -I -S -B tools/skynet_investigate.py 'ValueError: M130_TITLE_INVALID'
& $py -I -S -B tools/skynet_investigate.py --why 'scan_head@97'
& $py -I -S -B tools/skynet_investigate.py 'Увидел M141_M131_DISPLAY_SCHEMA_CHANGED. Какой набор проверок ведёт сюда по коду?'
```

В третьем примере `raw` должен пройти проверку типа и быть непустым, иначе функция раньше выбросит другое исключение или вернёт `raw`. Затем проверка разметки должна обнаружить меньше двух строк, неверный префикс первой строки или неверный маркер во второй. Каждая из трёх проверок и оба предшествующих выхода имеют Git-ссылку. Для R09 вывод другой: перебор `candidates` завершился, а `path.is_file()` ни разу не дал истинного результата. Пустой список тоже удовлетворяет условию. Ранний `return path.absolute()` объясняет, почему подходящий файл исключает переход к этой ошибке. [Проверки разметки](https://github.com/Daystat-debug/SkynetVS/blob/d7dafa045d8e32cce7a50318a0fe947cea0bb605/modules/developer_task_ui/app/context_search.py#L181-L189) · [Поиск Git](https://github.com/Daystat-debug/SkynetVS/blob/d7dafa045d8e32cce7a50318a0fe947cea0bb605/modules/developer_task_ui/app/git_source.py#L35-L39)

## Что считается доказанным

При обратном проходе ядро вычисляет, какие ветви должны пропустить управление к цели. `return` и `raise` закрывают продолжение. Для `for` отдельно учитываются исходы предыдущих итераций и условия текущей. `continue` может закрыть путь к строке на текущей итерации, сохранив возможность следующей. Условия с одинаковым продолжением по обеим ветвям исключаются из формулы. Механизм одинаков для диагностики, возврата и присваивания. [Анализ условий](../../../tools/skynet_control_conditions.py)

Область вывода — явные переходы внутри функции при нормально завершившихся вычислениях и конечном переборе. Значение выражения относится к строке и итерации его проверки. Утверждения о конкретном запуске, значениях аргументов и происхождении данных требуют собственных свидетельств. При существенном неподдерживаемом переходе отдаётся `insufficient` с пустым списком утверждений. Обычный межфункциональный поиск 0.4 сохраняет доказанные звенья и явно маркирует такое объяснение причины как `partial`. Для структурированного результата доступен `--json`.

Для точного кода или координаты модель не нужна. В свободном вопросе с однозначным кодом либо координатой локальная Qwen классифицирует только намерение. Цель берётся из вопроса, снимок и пять путей определяет хост. Модель не получает исходники и не формулирует утверждения. Остаются дедлайн 25 секунд, лимит шести шагов и 96 ссылок. Если буквального ориентира нет, требуется уточнение. [Выбор цели](../../../tools/skynet_causal_query.py) · [Интеграция в хост](../../../tools/skynet_investigate.py)

## Сохранённые неудачи и стоимость

- **T08.** На вопрос «Меня интересует смысл M127_INPUT_TOO_LARGE. Какие проверки к нему приводят?» ядро в обоих прогонах запросило уточнение. При повторе модель явно вернула `other`. При передаче одного кода тот же анализатор выдаёт полное объяснение.
- **T09.** Для текущей итерации чтения Git-объектов надо учесть возможные исходы предыдущих. В теле цикла есть `try/except`, взаимодействующий с `continue`. Анализатор остановился. Эталон засчитывает это как нерешённую положительную задачу. [Тело цикла](https://github.com/Daystat-debug/SkynetVS/blob/d7dafa045d8e32cce7a50318a0fe947cea0bb605/modules/developer_task_ui/app/context_search.py#L106-L134)
- **R05/R09/R14.** Для R05 дано точное уточнение о двух местах. Для R09 доказано условие раннего возврата. Для R14 намерение распознано, но предшествующий `while` оставляет причину недоказанной. Отказ удовлетворяет проверке достоверности. Полного ответа на исходный R14 по-прежнему нет.
- Полная CLI для точной диагностики заняла 687, 605 и 620 мс. Один запуск разговорного T03 с отдельным стартом Qwen занял 17,76 с. Это замеры одного Windows-стенда. Всего было 16 генераций: одна разработческая, семь в основном прогоне, семь при новом запуске модели для проверки и одна в замере CLI. При повторе совпали все семь решений и конечные ответы. [Замеры CLI](cli.json) · [Повтор с локальной моделью](live_replay.json)

## Воспроизведение проверок

```powershell
$py = '.\.venv\Scripts\python.exe'
& $py -I -S -B tools/test_control_conditions.py
& $py -I -S -B tools/eval_control_conditions.py verify
& $py -I -S -B tools/eval_control_conditions.py verify --compare-direction
& $py -I -S -B tools/eval_control_conditions.py verify --live-model
& $py -I -S -B tools/eval_diagnostic_path.py verify
```

Обычный `verify` повторно читает Git, строит доказательства и использует сохранённые решения классификатора. `--live-model` повторяет и классификацию. Проверены подмена URL, подмена координаты, смена HEAD и ограничение шагов. Результаты Core 0.1–0.4 воспроизведены из архивов. Для 0.4 дополнительно сверяются действующие ответы на ранее решённые вопросы. Более строгая проверка удерживает прежний R17 из-за обработчика в предыдущих итерациях; архивный ответ сохранён. Также прошли 38/38 архивных решений статических инструментов, 14/14 пар профилей, 11 сценариев обзора изменений и 32/32 проверок пакетных границ. Полный production pipeline в эту проверку не входил.
