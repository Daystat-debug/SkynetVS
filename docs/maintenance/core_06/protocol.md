# Core 0.6. Проверка маршрута от входа до результата

База — `7b0dab53f726e649e4b3bbd899391c97a2269b7d`. Исследователь получает входную функцию и наблюдаемый ориентир. Ориентиром может служить функция, возвращаемое поле, код диагностики или инструкция. Цель — привести один статический маршрут, связать аргументы с формальными параметрами на тех же местах вызова и предъявить условия каждого необходимого перехода. Для несовместимого литерала допустим вывод только о конкретном маршруте. Неизвестные предикаты остаются условиями. Достижимость на реальном входе отдельно не устанавливается.

Фиксируем реализацию до составления новых вопросов, затем отдельным коммитом фиксируем вопросы, эталонные исходные строки и факты до измерения. Добавляем задачи на одноразовых Git-снимках с ветвлением и переименованием. Их генератор фиксируется до получения seed из SHA реализации. Проверяем отдельно локальный случай, связи между файлами, конкурирующие маршруты, недостаточность данных и границы. Никаких исправлений по ответам контрольного набора.

Сравнения: принятый Core 0.5 на том же вопросе, первый кратчайший маршрут с проверкой после выбора, перебор маршрутов в ширину с повторной попыткой и общим кешем, проверка ограничений до углубления. У инструментальных вариантов одинаковые цели, проверяющие процедуры, лимит шести обращений, 96 уникальных ссылок, общий предел рассматриваемых состояний и дедлайн 25 секунд. Фиксируем полноту доказательств и смысл публичного ответа отдельно от успешной проверки Git-ссылок. Измеряем ошибки, необоснованные утверждения, шаги, стоимость модели и задержку. Возможное равенство или проигрыш сильной простой альтернативе сохраняется в отчёте.
