# M154: работа с экспериментами и переносами в main

Договорённость обновлена 26 октября 2026 года: в `main` переносим законченные
блоки связанных изменений. Отдельные небольшие исправления продолжаем
коммитить и отправлять в экспериментальную ветку вместе с результатами проверок.

## Ветки и история

- Рабочая экспериментальная ветка:
  `experiments/m154/ab2966ba927e474fb43df4c7d01799f1`.
- `main` содержит подтверждённые законченные блоки. Между такими переносами
  эксперименты могут опережать его на несколько коммитов.
- Каждый подготовленный пакет включает конкретные изменения, регрессионные
  проверки и обезличенный отчёт. Отрицательный результат `FAIL` тоже сохраняется
  в истории эксперимента для последующего разбора.
- Граница переноса определяется завершённым результатом, а не фиксированным
  количеством коммитов. Перед публикацией проверяем состав всего блока и его
  работу на актуальном `main`.
- Публикация готового блока выполняется одним подготовленным запуском.
  Промежуточные исправления сами по себе не запускают публикацию в `main`.
- В экспериментальной истории сохраняются причины ошибок, их исправления
  и тесты. Эти записи не переобучают веса внутреннего агента автоматически.

В публичные отчёты включаем статусы, версии инструментов и хеши проверенных
файлов. `.env`, модели, исходные пользовательские журналы и приватные данные
остаются вне Git. Переключение веток и синхронизация локального `main` выполняются
отдельно от публикации, с сохранением незакоммиченной работы.

## Текущий блок: достоверность результатов конвейера

**Статус: открыт. Автоматический перенос этого пакета в main отложен до
завершения блока.**

Исходный экспериментальный commit:
`df25fd355178e2c8a84f1e025a74bccd5ec4c0c7`.
Подтверждённый `main` на момент начала блока:
`f5d2a094e88940f6576097fcdc368ac0e0cbc746`.

Первый пакет исправляет представление исходов шагов в `tools/pipeline.py`:

| Статус | Значение |
|---|---|
| `PASS` | Запущенный шаг завершился успешно |
| `FAIL` | Шаг завершился с ошибкой, не смог запуститься или был прерван |
| `SKIP` | Зарегистрированный шаг неприменим на текущей платформе и пропущен |
| `NOT_RUN` | До шага не дошли из-за остановки предыдущего |

Для платформенных пропусков используется явный список существующих Windows-
проверок, которые уже завершаются пропуском с кодом 0 на неподходящей платформе.
Проверки, намеренно возвращающие ошибку без Windows, сохраняют это поведение.
Один лишь суффикс `_windows.py` не является основанием для пропуска.

Пропущенные шаги не входят в число `PASS`. Если поток завершился с пропусками,
итог помечается `INCOMPLETE`. Код процесса 0 для такого завершения сохраняется
для совместимости: он означает отсутствие ошибки процесса, а не доказательство,
что все проверки были выполнены. После ошибки оставшиеся шаги получают
`NOT_RUN` и не запускаются. Статусы относятся к шагам конвейера, а не ко всем
внутренним случаям каждого дочернего тестового набора.

Существующие команды и состав потоков сохраняются. Это также сохраняет
контракт статических потребителей `available_flows()` в developer inventory.

### Оставшаяся работа в этом блоке

1. Согласовать машиночитаемую сводку с отображаемыми статусами и явно отмечать
   неполное выполнение при использовании результатов другими инструментами.
2. Уточнить описание команд, которые читают данные, строят отчёты или изменяют
   обучающие данные, и закрепить это в проверках и документации.
3. Проверить весь накопленный блок на Windows, затем подготовить один перенос
   его окончательной версии и отчётов на актуальный `main`.

Параметр `--no-log` отключает только файл журнала самого конвейера. Он не
отключает действия дочерних команд. В частности, `analyze` включает построение
correction memory, а `full` включает отчёты и экспорт данных; эти команды
не следует использовать как обозначение проверки без записей.

Регрессионный набор первого пакета запускается отдельно:

```powershell
& '.\.venv\Scripts\python.exe' -I -S -B -X utf8 tools/eval_pipeline_status.py
```

Он использует временные каталоги и безопасные подставные процессы. Реальные
потоки `check`, `analyze`, `full`, обучение, модели, аудиоустройства и native
Windows-операции при этом не запускаются.
