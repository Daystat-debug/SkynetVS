# Core 0.18. Протокол сравнения

Исходный снимок — `0c0f7916f28cbac2cfd6616b320946330b1715fe`. Проверяем гипотезу, что раздельное описание события в вопросе и в источнике позволяет хосту проверять роли и полярность без модельного выбора номера кандидата. Обучение не проводится. Тексты обеих сторон интерпретируются раздельно. Код, координаты, ссылки, состав пула, получение фактов и решение о публикации остаются у хоста.

1. Сохранить планировщик 0.16, два вызова локального поставщика максимум на вопрос, существующие границы и проверки. Сравнить полный путь с 0.16 и тремя вариантами 0.17. Сопоставить с выбором по множеству концептов без их ролей на тех же извлечённых представлениях. Раздельно учитывать лексические результаты на тех же кандидатах. Цитаты и ссылки на ранее названный объект оцениваются в полном пути, отдельно от прямого поиска.
2. Сначала закрепить реализацию, проверки и оценщик. Затем написать и закоммитить новую контрольную серию и эталоны до измерения. Серия авторская. Фикстуры добавляются только в проверяемые временные Git-снимки прежнего лабораторного профиля. Включить изменения участника, состояния, направления, отрицания, пересказ с сохранением смысла, неопределённость, отсутствующий объект, зависимые и недоступные требования. Сопоставлять одинаковые вопросы и снимки. Исторические данные использовать только отдельно.
3. Контролируемая проверка использует полный закрытый список событий предметной области в смешанном порядке. У корректного положительного вопроса в нём обязательно есть цель. Никакие координаты ответа не передаются механизму сравнения. Проверить извлечённые обе стороны, известный смысл только вопроса, только карточек и обеих сторон. Эталон включает участника/источник, предикат, предмет, адресата/назначение и полярность. Неуказанная характеристика оставляет несколько возможных гипотез. Рубрика фиксирует допустимые эквиваленты по полям; алгоритм их не видит. Зафиксировать также случаи с эталонными противоречиями по ролям и полярности.
4. Для извлечения оценивать валидность формата, правильность отдельных полей и целой рамки. Для решений — правильные привязки, чужие привязки, отказы, истинные и ложные обнаружения противоречий. В полном пути использовать независимую рубрику 0.17 с проверкой содержимого и Git-ссылок: кандидаты, доставленные факты, полный ответ, полезный частичный, ложная полнота и причины пробелов. Учитывать шаги, генерации, токены, медианную задержку и запуск поставщика отдельно. Сохранять исходные ответы модели и хеши запросов для воспроизведения без генерации.

Преимущество требует улучшения полезных конечных ответов при сохранении надёжности. Срабатывание сравнения на ручных рамках или сокращение числа утверждений само по себе недостаточно. Замеры после фиксации контрольной серии завершают эксперимент.
