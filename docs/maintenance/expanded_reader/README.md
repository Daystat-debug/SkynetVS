# Пять исходников в статическом читателе SkynetVS

На снимке `ee908b0` читатель прослеживает количество функций-кандидатов от накопления строк в M127 до публичного отчёта M134. Для второго модуля, M126, он правильно объясняет счётчик токенов заголовка и находит один из двух прямых вызовов ранжировщика. Проверка охватывает два сценария одной подсистемы.

## Запуск

Из корня SkynetVS на Windows с установленным проверяемым комплектом M289 и Git в стандартном каталоге:

```powershell
.\.venv\Scripts\python.exe -I -S -B tools/skynet_scope_lab.py --compose "Кто вызывает rank_symbols и откуда в отчёте число функций-кандидатов?"
.\.venv\Scripts\python.exe -I -S -B tools/skynet_scope_lab.py --flow "Откуда берётся symbol_candidates?"
.\.venv\Scripts\python.exe -I -S -B tools/skynet_scope_lab.py --auto "Кто вызывает rank_title_only?"
.\.venv\Scripts\python.exe -I -S -B tools/skynet_scope_lab.py --calls "Кто вызывает format_context?"
```

Без вопроса запускается диалог, выход — `/exit`. Список файлов и SHA печатаются при запуске. Лабораторный CLI всегда читает один закреплённый коммит, в том числе после переключения ветки.

## Область и достоверность

У штатного CLI область задаёт `retrieval284.SCOPE`. Его `local_reader` проверяет комплект Developer Tasks и загружает доверенный читатель Git из частной копии. Среди байтов, исследуемых в эксперименте, есть сам `git_source.py`. Поэтому лабораторный вход использует отдельный транспорт к установленному Git. Он проверяет пакет M289, использует закреплённые M254 Snapshot и функции проверки ссылок, запускается в Windows Job. Анализируемые модули поступают только как UTF-8 из Git в AST. Вопрос и исходный текст не поставляют аргументы подпроцессу.

Разрешены три исходных пути из штатного комплекта и ровно два дополнительных файла — [m127_symbol.py](../../../modules/developer_task_ui/app/retrieval/m127_symbol.py) и [m126_rank.py](../../../modules/developer_task_ui/app/retrieval/m126_rank.py). Git получает буквальный путь из списка в фиксированном дереве. Только OID обычного файла из такого ответа допускается к проверке размера и чтению. Сохраняются предел 256 КиБ на файл, общий предел Snapshot, сверка Git blob, SHA-256 исходника и диапазона строк. Регулярные файлы рабочего дерева не служат источником анализируемого текста. Транспорт отключает сетевые протоколы, lazy fetch, replace-объекты и hooks. Модель в этих четырёх режимах отсутствует. Это профиль доступа доверенного локального инструмента. Ключи Python и управление временем жизни процессов не предоставляют песочницу ОС.

## Парное измерение

[Вопросы и рубрика](questions.json) закреплены в `2d4b8a3`. В обоих профилях один источник `ee908b0`, один проверяющий ссылки и один транспорт. В колонке «3» выполнены прежние алгоритмы с прежним списком файлов. Сам штатный загрузчик UI в измерении не запускался. В первой итерации (`9db1c91`) изменена только область анализа. Измерялись S1 и S2. S1 установил место вызова и прервался внутри M127, S2 запросил уточнение. Старый обход видел возвраты вложенных помощников как альтернативные возвраты внешней функции. [Журнал первой итерации](discovery.json).

Во второй итерации (`aa402c7`) расширенный профиль различает области видимости возвратов, удерживает трассу для генераторов и приводит начальное присваивание и видимые операции пополнения списка. Переносные T1–T5 впервые предъявлены после коммита алгоритма. Полные тексты обеих выдач, ссылки, статусы, хеши и времена сохранены в [парном журнале](paired.json). Время в таблице — один прогон обработки вопроса на уже открытом снимке, без запуска Python, открытия файлов и независимой перепроверки измерителем.

**Ручная оценка конечных ответов.** Из четырёх положительных вопросов штатная область дала четыре уточнения. Расширенная дала два полных и два частичных ответа. Обе частичные выдачи относятся к одному перенесённому сценарию. В трёх ограниченных и отрицательных случаях оба профиля сохранили ожидаемую границу. В пятифайловой выдаче проверены 32 появления ссылок, 19 уникальных диапазонов. При сравнении текстов с исходниками ложных связей в этих семи ответах не обнаружено.

- **S1/S2.** M127 добавляет строку на каждой завершённой итерации по символам и берёт `len(rows)`. В коде `limit` применяется при построении списков выдачи. M130 читает `sym['symbol_candidates']` и возвращает `function_candidates_total`. M134 переносит это значение в `candidate_functions`. Форматировщик действительно читает такой ключ, но передача именно этого отчёта форматировщику в пяти файлах не доказана. [Накопление и длина](https://github.com/Daystat-debug/SkynetVS/blob/ee908b063c31a5c9dd8e97ef64ca2ddc3b423235/modules/developer_task_ui/app/retrieval/m127_symbol.py#L87-L111), [перенос через rank](https://github.com/Daystat-debug/SkynetVS/blob/ee908b063c31a5c9dd8e97ef64ca2ddc3b423235/modules/developer_task_ui/app/retrieval/m130_rank.py#L125-L135), [публичное поле](https://github.com/Daystat-debug/SkynetVS/blob/ee908b063c31a5c9dd8e97ef64ca2ddc3b423235/modules/developer_task_ui/app/context_search.py#L153-L167).
- **T1/T2.** В M126 `query = list(dict.fromkeys(tokens(title)))`, а `title_token_count = len(query)`. Читатель нашёл присваивание `files = rank_title_only(title, old_sources, top_n=10)` в M130. Второй прямой вызов находится в блоке запуска M126. CLI оговаривает предел поиска, однако статусы `composed` и `call_sites` сами по себе завышают полноту для вопроса обо всех вызывающих. Для T1 объединитель также не установил связь конкретного результата с возвращаемым полем. В этом случае он связывает только места вызова, лежащие на обратной трассе значения, а трасса локального поля начинается внутри производителя. [Подсчёт](https://github.com/Daystat-debug/SkynetVS/blob/ee908b063c31a5c9dd8e97ef64ca2ddc3b423235/modules/developer_task_ui/app/retrieval/m126_rank.py#L34-L47), [поле и второй вызов](https://github.com/Daystat-debug/SkynetVS/blob/ee908b063c31a5c9dd8e97ef64ca2ddc3b423235/modules/developer_task_ui/app/retrieval/m126_rank.py#L84-L104).

## Воспроизведение

```powershell
.\.venv\Scripts\python.exe -I -S -B tools/eval_expanded_reader.py verify
.\.venv\Scripts\python.exe -I -S -B tools/eval_expanded_reader.py regression
.\.venv\Scripts\python.exe -I -S -B tools/test_expanded_reader.py
```

Повтор совпал с парным журналом по решениям, текстам и ссылкам. На трёх файлах для 38/38 прежних вопросов совпали решения, утверждения, диапазоны с хешами и установленные связи. Пройдены прежние наборы `test_skynet_explain`, `test_flow_reader`, `test_auto_reader`, `test_composed_reader` и 32/32 проверки `tools.eval_package_boundaries`. Новый тест проверяет в том числе запрет произвольных путей и OID до запуска Git, подмену байтов, вложенные возвраты, генераторы и подмену встроенного имени. Обе существенные итерации исчерпаны, генераций локальной модели — 0.

Следующий предлагаемый шаг — поддержать прямые вызовы в охраняемом блоке запуска модуля и указывать охват в результате поиска вызывающих. Это проверяемый пропуск сразу в T1 и T2 внутри уже разрешённых пяти файлов.
