**Windows и Git.** Два HWA-оценщика проверяют физические байты. Восемь путей воспроизводят закреплённые SHA при явно заданных окончаниях строк: четырём нужен LF, четырём CRLF. Правила записаны в `.gitattributes`; это проверено в свежем checkout. Эти правила начинают действовать на существующие файлы при следующем извлечении из Git. Отдельный дефект двух тестов Developer Tasks: после `patch.dict` в Windows дочерний Git терял явно пустое значение `GIT_CONFIG_VALUE_0` и завершался с кодом 128 на создании фикстуры. Общий helper теперь передаёт копию `os.environ` обоим вызовам Git. Все настройки, в том числе пустые, передаются как были. [Атрибуты](../../../.gitattributes) · [Общий helper](../../../tools/eval_developer_task_workspace.py) · [Побайтовая сверка](pins.json)

**Конфликт, требующий отдельного решения.** Оба HWA-оценщика требуют для `modules/actions.py` SHA-256 `dfdc9c8f…1661`. Он точно соответствует содержимому `09f8708f` с CRLF. У текущего файла `29fc2a35…6862` с CRLF и `086f8e35…3922` с LF. Коммиты `1d7ee5f6` и `85e08d38` добавили реальные обработчики, в том числе открытие Developer Tasks и управление жизненным циклом. Нынешний `main.py` передаёт `developer_task_ui_launch`; исторический конструктор такого параметра не принимает. Восстановление старого файла сломает запуск. Подмена SHA, проверка другого дерева вместо текущего и пропуск шага изменили бы смысл проверки. ### Воспроизведение

```powershell
$py = './.venv/Scripts/python.exe'
& $py -I -B tools/navigation_lab/check_reminder_compat.py
& $py -I -B tools/navigation_lab/check_host_snapshot.py 793cd41
& $py -I -B tools/navigation_lab/check_host_snapshot.py 95451f3
& $py -I -B tools/navigation_lab/check_host_snapshot.py 95451f3 --fit --diagnose-tail
```

Без `--fit` используется временная копия установленной `models/nlu_intent.joblib`. С `--fit` обучение и прогон выполняются в одноразовой копии, которая затем удаляется. Три приведённых прогона host check ожидаемо возвращают код 1; их диагностические итоги выводятся в JSON. Выполнены 10/10 проверок Navigation 0.1, 32/32 границ пакетов, 48/48 guest request и 34/34 binding. Проверки исторических результатов Core воспроизвели 15/15 в 0.1, 26/27 в 0.2 с прежним пропуском T5, а в 0.3 — 8/9, 14/14 и 9/9 на трёх сериях. Исторические регрессии воспроизводятся прежними командами `tools/eval_investigation.py verify`, `tools/eval_producer_investigation.py verify` и `tools/eval_argument_flow.py verify`.
