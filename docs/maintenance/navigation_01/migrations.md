# Реестр миграций SkynetVS

Базовая ревизия `bceec9c`. Статусы описывают очередь разработки. Следующая единица приёмки — **M01**, первая контролируемая миграция точки входа разработчика. Первое физическое изменение структуры production — **M04**, с отдельным входным условием. Владелец в таблице обозначает ответственную подсистему. При старте исполнитель фиксирует исходный SHA, а при закрытии — итоговый SHA, проверки и сохранившиеся исключения в соответствующей строке реестра.

| ID, приоритет, состояние | Владелец и изменение | Зависимости и основной риск | Критерий приёмки и откат |
|---|---|---|---|
| M01 · P0 · следующий | Документация и tooling. Перевести вход разработчика с корневого `project_inventory.md` на короткий маршрут из `README.md` к `docs/maintenance/navigation_01/README.md`; указать дату и назначение `CURRENT_STATE` в точке чтения. Уточнить в `tools/project_inventory.py` назначение старого отчёта и опциональный путь в scratch. | Принятый Navigation 0.1. Проверить оба файла с упоминаниями `project_inventory` в дереве, запуск генератора по умолчанию и с явным `--out` в одноразовом checkout. Старые внешние команды и локальные метаданные — риски совместимости и публикации. | По чистому checkout разработчик доходит от README до источника и проверки напоминаний; сохранён старый способ явно получить локальный отчёт. Обычный маршрут не создаёт tracked-снимок. Ссылки и поведение CLI проверены. Откат — один commit с маршрутом и изменением default. Отдельная запись решения о выводе старого файла из Git. |
| M02 · P1 · после M01 | Документация экспериментов. Создать `docs/maintenance/INDEX.md` со строками «возможность → принятый SHA → отчёт → контрольная команда → потребители». Произвести поиск путей и коротких имён в коде, Markdown, JSON и истории. | Все выбранные строки разрешаются в Git; ссылки из `eval_investigation.py` и `eval_m289_scoped_retrieval.py` по-прежнему адресуют прежние blobs. Добавление/откат индекса одним docs-коммитом. Физическое перемещение архива — только по отдельной записи с проверенными потребителями. |

Завершить **Inventory V2** для `main.py` и `modules/**`: каждому модулю назначить владельца, целевой пакет или текущий стабильный путь, публичные имена, разрешённые входящие/исходящие зависимости. M02 может идти отдельно. | На каждый исходный путь определён владелец и способ сохранения публичного интерфейса; для пилота сверены все импортеры, тесты, регистры и профили, зафиксирован список допустимых рёбер и исходный результат проверок. Неясные или защищённые модули получают явный статус hold. При расхождении вернуть карту на ревью, дерево остаётся прежним. |

Преимущество — только stdlib внутри листового модуля. Проверить внешние импорты, идентичность класса, циклы, сохранённые ссылки, policy и привязки хеша. Старый путь допустим только как явно одобренный фасад со сроком пересмотра. | Один домен, один обратимый commit. Сравнить типы, ошибки и результаты на существующих примерах; запустить eval дат, команд и runtime напоминаний, guard импорта старого пути с перечисленными исключениями, пакетные границы, полный согласованный pipeline. При расхождении или конфликте с закреплённым профилем остановить перенос и вернуть целиком commit. |

Первый кандидат — проверки напоминаний из `tools/eval_reminder_*.py` в `tools/evals/reminders/` с совместимыми точками запуска. | M04, принятые границы домена и очередность Phase 3. Строковые команды pipeline, рабочая директория и прямые вызовы из документации важнее наличия импорта. | Прежняя команда из корня и запись pipeline дают те же коды, семантику и класс эффектов; protected guards остаются на месте, production не импортирует tools. Однодоменный commit и его полный откат. |

Проверить pinned источники, исторические ссылки, потребителей и поведение реального класса. | На рабочем snapshot остаётся одно определение; eval хранилища и сервиса дают исходные результаты. Старые Git-ссылки воспроизводятся на старом SHA. При нарушении пина отложить изменение, без обновления эталона ради PASS. |

Также отдельно проверить потребителей старого `project_inventory.md` после M01. | У `test.py` есть действие при импорте, compile-шаг и ссылки в защищённых списках и vendor. Для `project_inventory.md` нет доказательств об использовании вне репозитория. Решения по двум файлам принимать раздельно. | Для desktop — эквивалентная compile-only проверка, сохранённая защита путей и отдельное решение владельца. Для inventory — согласованная замена, подтверждённый вывод генератора и явная авторизация удаления tracked-копии. Пока критерии открыты, оба пути сохраняются. |

**Правило входа в миграцию.** До правки открыть исходник, прямого потребителя, профиль/манифест и адресную проверку. Получить реальные строки через `git show <sha>:<path>`, проверить строковые и динамические ссылки. Для изменения проверяемого комплекта нужен отдельный проект совместимости. Записи текущего реестра не меняют состояние фаз или полномочия продукта. [Карта и факты](architecture.md) · [Roadmap Phase 2, Phase 3 и RC044](../../architecture/SKYNETVS_ARCHITECTURE_ROADMAP_V1.md)
