# Обзор сохранённых изменений относительно HEAD

Из корня проекта на Windows с проектным Python и прежним проверяемым комплектом M289:

```powershell
.\.venv\Scripts\python.exe -I -S -B tools/skynet_core_explain.py --changes
.\.venv\Scripts\python.exe -I -S -B tools/skynet_core_explain.py "Что я изменил относительно Git HEAD и какие связанные участки кода стоит проверить?"
.\.venv\Scripts\python.exe -I -S -B tools/skynet_core_explain.py --changes --json
.\.venv\Scripts\python.exe -I -S -B tools/eval_change_review.py verify
```

Первые две команды открывают один и тот же фиксированный сценарий. Он сравнивает пять разрешённых файлов на диске с их версиями в HEAD, включая сохранённые изменения вне индекса. Для изучения конкретного вопроса об одном снимке по-прежнему доступны прежние режимы.

## Как читать результат

На контролируемой правке ограничения размера отчёт локализовал условие внутри цикла в `rank`. При замене строгого сравнения на нестрогое для обычных чисел меняется выбор ветви при точном равенстве. Полезная проверка — сравнить результат на границе, непосредственно ниже и выше неё. В том же файле отдельно обнаружена замена аргумента `top_n` с 10 на 4. Указаны получатель результата, определение `rank_title_only` и прямые вызывающие места для `rank`, включая `search_repository`. Реальные значения на запуске не измерялись.

На другой правке `search_repository` стал брать значение поля отчёта из другого счётчика. Читатель указал выражения до и после и место чтения того же ключа в `format_context`. Сравнить эти места полезно на входе, где значения двух счётчиков различаются. Совпадение ключа само по себе не устанавливает передачу конкретного экземпляра отчёта форматировщику.

Каждая структурная разница содержит путь, функцию или область модуля, доступные стороны изменения и проверенные координаты. В JSON `related` различает прямой вызов, разрешённую цель изменённого вызова и отдельное чтение того же ключа. `possible_effect` и `suggested_check` — интерпретация и предложение разработчику. Список проверок не является результатом их выполнения. [Сравнение и формирование отчёта](../../../tools/skynet_change_review.py)

## Достоверность и область

Хост закрепляет SHA HEAD, захватывает рабочие байты и сверяет ссылки с соответствующим снимком. Для подбора связанных мест повторно используются `calls.lookup` и индекс производителей и потребителей полей `flow.Slice`. Цель изменённого вызова связывается по его координатам AST. Для удаления анализируются старые места в HEAD, для сохраняющегося или добавленного участка — места в рабочем снимке. Выбор этих операций детерминирован структурой правки.

Перед выдачей решения прежний `publication_guard` повторно проверяет все пять рабочих файлов и удерживает их дескрипторы. Под этой защитой хост ещё раз сверяет фактический HEAD с закреплённым SHA. При расхождении отчёт удерживается целиком. Печать уже принятого отчёта не продлевает блокировку файлов. Ссылки на сохранённый код содержат локальный путь, строки и ID снимка. После последующего сохранения локальный путь может открывать новые байты.

## Результаты

| Контроль | Проверенный исход |
|---|---|
| Чистые байты и изменение только в шестом файле | В обоих случаях ноль находок в разрешённой области |
| Добавление комментария | Одна текстовая правка, обычный AST совпал, связанных вызовов не заявлено |
| Вложенное условие и аргумент вызова | Две отдельные правки, обе версии выражений, разрешённая цель и вызывающие места |
| Замена источника поля отчёта | Одна правка поля и одно место чтения того же ключа |
| Удаление и добавление определения | Две односторонние находки. Переименование не заявлено |
| Некорректный Python, смена HEAD, сохранение файла во время анализа | Три отказа, ни одного частичного отчёта |
| Перенос на условие в M127 и поле конструктора словаря в M130 | Обе правки локализованы. Для одноимённых функций не выдан ложный вызывающий участок |

**11/11 контролируемых сценариев**, из них девять по рубрике до реализации и два переноса после фиксации алгоритма. Независимая сверка сравнила 39 появлений ссылок с байтами соответствующей версии. В первом варианте `4521347` проверка двух правок не прошла: вместо вложенного предиката анализатор выдал весь цикл как одну инструкцию. В `d3b5dbd` обход неизменённого заголовка цикла доведён до изменённого условия. Эта ошибка не включена в успешные результаты первого варианта.

CLI проверен также в каталоге рабочего проекта через текст, JSON и русский вопрос. Содержимое этой выдачи не сохранялось. Все записанные метрики получены во временной копии из принятого коммита, без пользовательских незакоммиченных байтов. Журнал содержит только имена сценариев, счётчики и причины отказа. ### Ограничения

Обзор охватывает пять существующих читаемых Python-файлов и сохранённые байты. Ошибка чтения или синтаксиса блокирует выпуск. Совпадение обычного AST не оценивает внешние инструменты, обработку комментариев или последствия перемещения строк для диагностики. В файле со структурной правкой перечисляются структурные изменения; сопутствующие комментарии и пробелы отдельно не инвентаризируются. Для сложной перестройки блоков возможен результат на уровне инструкции или отдельных несопоставленных фрагментов. Превышение бюджета в 48 находок удерживает обзор. Динамическая диспетчеризация, полный граф проекта и подтверждение дефектов требуют других доказательств.

Сохранены 38/38 архивных решений, 14/14 предыдущих пар и 32/32 проверок архитектурных границ. Расход — две существенные итерации, ноль генераций Qwen.
